# Rus-Trader

Автоматизированный торговый бот для российского фондового рынка (MOEX). Собирает рыночные данные (топ-50 ликвидных акций TQBR, часовые свечи, новости), анализирует их через DeepSeek R1 и автоматически исполняет сделки через T-Invest API.

## Архитектура

```
MOEX ISS API → топ-50 тикеров по объёму (TQBR)
      ↓
T-Invest SDK → резолв тикеров в UID, проверка tradability
      ↓
T-Invest SDK → часовые свечи за неделю (параллельно)
      ↓
MOEX ISS API → новости за 24ч → фильтр по тикерам
      ↓
T-Invest SDK → текущий портфель
      ↓
Indicators   → RSI(14), EMA(9/21), ATR(14), RelVol, S/R уровни
      ↓
Screener     → фильтрация тикеров по силе сигнала
      ↓
DeepSeek R1  → анализ индикаторов + OHLCV + новостей → JSON решения
      ↓
TradeGuard   → pre-validation (RSI > 80, время суток, лимиты)
      ↓
Executor     → лимитные ордера + SL/TP + trailing stop
      ↓
SQLite + Telegram + Web Dashboard
```

**Стек:** Go, T-Invest API (gRPC), MOEX ISS API, DeepSeek R1, SQLite (GORM), Telegram Bot API

## Быстрый старт

### Требования

- Go 1.22+
- Токен T-Invest API ([получить](https://www.tbank.ru/invest/settings/))
- API ключ DeepSeek ([получить](https://platform.deepseek.com/))

### Настройка

```bash
cp config.example.yaml config.yaml
# Отредактируйте config.yaml — укажите токены
```

### Запуск

```bash
# Собрать всё
make build

# Запустить бота
make run

# Docker
make docker
```

Dashboard доступен на `http://localhost:8080`

## Торговые улучшения

### Технические индикаторы
Бот автоматически рассчитывает RSI(14), EMA(9), EMA(21), ATR(14), относительный объём и уровни поддержки/сопротивления для каждого тикера. Индикаторы передаются в AI для более точного анализа.

### Предварительный скрининг
Перед отправкой в AI тикеры ранжируются по силе технического сигнала (RSI-экстремумы, EMA-кроссоверы, аномальные объёмы). В анализ попадают только самые перспективные кандидаты.

### Trailing Stop
При включении (`trailing_stop_enabled: true`) бот автоматически подтягивает SL:
- При достижении 50% пути к TP — SL переносится на безубыток
- При достижении 75% пути к TP — SL фиксирует 50% прибыли

### Масштабирование позиций
Размер позиции зависит от уверенности AI: confidence 90+ = 100%, 80-89 = 75%, 70-79 = 50% от `max_position_rub`.

### Лимитные ордера
При `limit_order_slippage > 0` вместо рыночных ордеров используются лимитные с указанным отступом от текущей цены, что снижает проскальзывание.

### Фильтр по спреду
Перед покупкой проверяется bid/ask спред. Тикеры со спредом выше `max_spread_pct` пропускаются.

### Защита от плохих SL/TP
Executor автоматически корректирует решения AI:
- **Инвертированный SL** (SL >= цена входа) → пересчёт по `default_stop_loss_pct`
- **Слишком узкий SL** → расширение до динамического пола `max(min_stop_loss_pct, atr_sl_multiplier*ATR/price*100)` и жёсткий cap 6%
- **Слишком узкий TP** (< `min_take_profit_pct`) → расширение до минимума
- **Плохой R:R** (TP/SL < `min_risk_reward_ratio`) → увеличение TP

Динамический SL на основе ATR даёт широкий стоп волатильным тикерам (RUAL, WUSH) и не выбивает по рыночному шуму, а по спокойным оставляет минимум 2%.

### Фильтр тренда
При `require_uptrend: true` TradeGuard блокирует BUY, если EMA9 < EMA21 (нисходящий тренд). Это предотвращает "ловлю падающих ножей" — покупку перепроданных бумаг, продолжающих падение.

### Pre-validation решений
TradeGuard механически блокирует BUY при RSI > 80 (перекупленность) и в последний час торгов (17:50-18:50 MSK).

### Circuit Breaker
При превышении дневного убытка (`max_daily_loss_rub`) бот прекращает открывать новые позиции до следующего дня. Защищает от каскадных потерь в неудачные дни.

### Фильтр убыточных тикеров
Тикеры, по которым были убытки за последние N дней (`recent_loss_cooldown_days`), временно блокируются для покупки (по умолчанию 1 день, чтобы не выжигать половину ликвидного списка из-за одной неудачной сделки). Дополнительно `max_losing_streak_per_ticker` блокирует тикеры, по которым накопилось N+ убыточных сделок подряд — этот фильтр точечнее и не зависит от времени.

### Market Context
В промпт передаётся общий фон рынка: среднее изменение по всем анализируемым тикерам за 1/3/7 дней и режим (`uptrend`/`downtrend`/`range`/`mixed`). Помогает модели адаптироваться к общим условиям вместо опоры на жёсткие запреты.

### Фильтр волатильности
Guard блокирует BUY для тикеров с ATR < `min_atr_pct` — если дневная волатильность слишком низкая, тикер не может дать необходимое движение для целевого TP 3%+.

### Минимальный score скринера
Тикеры с техническим score ниже `min_screener_score` не попадают в анализ AI (кроме тикеров с открытыми позициями). Снижает число шумовых сделок.

### Контекст серии убытков
AI получает информацию о текущей серии убыточных сделок подряд. При 3+ убытках подряд промпт содержит предупреждение о необходимости повышенной осторожности.

### Статистика в промпте
AI получает агрегированную статистику за 7 дней: win rate, средний профит/убыток, худшие тикеры — для более осознанных решений.

## Phase 1: Smart Trading Pipeline

### Текстовые признаки вместо OHLCV-таблиц
Вместо сырых числовых таблиц AI получает осмысленные текстовые описания:
```
SBER (305.20): аптренд (EMA +0.8%), рост 3+ дней (+4.2%), объём повышен (1.8x), RSI 58 — нейтральный, у сопротивления 308.50 (0.5 ATR), ATR 1.5%, дивиденд 8.2% (отсечка через 12 дн).
```
LLM работает с текстом значительно лучше, чем с таблицами чисел — меньше ошибок в интерпретации.

### Дивидендный календарь (SmartLab)
Бот парсит SmartLab (`smart-lab.ru/dividends/`) для получения дат отсечки, размера дивидендов и доходности. Дивидендная информация включается в текстовые признаки тикеров с предстоящей отсечкой (в пределах `dividends.lookahead_days`). Кеш обновляется раз в `cache_ttl_hours` часов.

### Два AI-агента вместо одного
- **Screening Agent** — анализирует рыночные данные и ищет BUY-кандидаты. Не видит портфель — фокус только на рынке.
- **Position Manager** — управляет открытыми позициями (HOLD/SELL). Не видит рыночные кандидаты — фокус только на портфеле.

Оба агента работают **параллельно** (через `errgroup`). Если один упал — другой продолжает работу. Результаты объединяются и проходят через Guard → Executor.

### Trade Journal с LLM Daily Review
При каждой сделке сохраняется **trade outcome** — гипотеза при входе, текстовые признаки на момент входа, причина выхода, результат, длительность удержания.

Утром в первый торговый цикл LLM анализирует закрытые сделки за предыдущий день и генерирует **3-5 структурированных уроков** (pattern → observation → recommendation + confidence).

Уроки с confidence `medium`/`high` инжектятся в промпты обоих AI-агентов, позволяя боту учиться на своих ошибках между торговыми днями.

Конфигурация:
```yaml
dividends:
  enabled: true
  cache_ttl_hours: 12
  lookahead_days: 30

journal:
  enabled: true
  max_lessons_in_prompt: 5
  max_lesson_age_days: 7
  min_trades_for_review: 1

ai_agents:
  screening:
    max_chars: 16000
    max_tickers: 20
  position_manager:
    max_chars: 8000
  journal_review:
    max_chars: 12000
    model: ""  # пустое = основная модель
```

## Торговые часы

Бот активен в торговые часы MOEX: **10:00–18:50 MSK**, понедельник–пятница.

## Режим песочницы

По умолчанию бот работает в sandbox-режиме. Аккаунт создаётся автоматически и пополняется на 1,000,000 руб. Stop-ордера в sandbox не поддерживаются T-Invest API.

Для перехода на реальную торговлю установите `tinkoff.sandbox: false` и укажите `tinkoff.account_id`.
